1. “8 月份”按最近的 2026 年 8 月理解，窗口为北京时间 `2026-08-01 00:00:00 <= committer time < 2026-09-01 00:00:00`。旧仓本地 `main` 为 `79c08e51e1676c9795ae7c44eb22755e4a081d83`，最后提交为 8 月 26 日；非合并提交共 170 条。7 月末基线为 `1b7305f9097cd7bd6ce23720d89f2e6469641400`。
2. 比较当前可达代码的最终行为，结合提交 diff 区分新增、修正、测试、文档和后续已替代方案。提交标题带 `feat`、`dormant` 或历史验收记录，均不能单独证明当前默认可用。

4. 本轮在 Runtime 当前依赖声明、锁文件、OKF 和相关 Git 提交标题中未定位到“曾固定依赖旧 Gateway 的准确 SHA”。本任务不把 7 月末基线误称为当时使用方锁定版本，也不将旧仓最新 HEAD 称为线上部署版本。若后续找到实际依赖 SHA，再补充该点到 8 月末的精确增量。
5. “透特性”按两个维度评估：是否同步业务特性；如需同步，材料/执行配置应由哪一层传递。未知可选字段被保存或忽略，不代表该特性已接通。
