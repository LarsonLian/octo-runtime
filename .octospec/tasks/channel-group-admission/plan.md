# 恢复目标

默认 CLI/SDK 配置不填写群相关字段时，已授权发送者在 Bot 可访问群中明确 @Bot，消息应进入原任务链并回复原频道。用户确认启停与范围必须用不同字段表达，不做旧空名单语义兼容；不以取消权限检查、免 @、正文猜测或额外业务执行器恢复可用性。

| 配置 | 群/话题 | 私聊 |
| --- | --- | --- |
| groups_enabled 省略或 true | 开启群/话题入口，继续校验范围和其他条件 | 原规则 |
| groups_enabled: false | 关闭所有群/话题入口，优先于范围名单 | 原规则 |
| group_ids 省略、null 或 [] | 不增加本地群范围限制，仍检查其他准入条件 | 原规则 |
| group_ids: [G1] | G1 及 G1 下的话题可以继续检查 @；G2 拒绝 | 原规则 |
| 省略 allowed_sender_ids | 仅认证/注册所得 owner | 同样仅 owner |
| allowed_sender_ids: [] | 拒绝所有发送者 | 拒绝所有发送者 |
| allowed_sender_ids: [U1] | U1 替代默认 owner 名单，仍检查群范围和 @ | 仅 U1 |

例如 owner 在 G1 中 @Bot：省略、null 或 [] 都应处理；[G2] 不处理；groups_enabled: false 时无论名单如何都不处理群/话题，但 owner 私聊仍处理。U2 不在发送者名单时，即使在 G1 明确 @Bot 也不处理。G1____T1 按 G1 校验范围，实际回复仍留在 G1____T1。Bot 已加入群不等于群内每个人自动取得触发权限。

groups_enabled 只接受布尔值，null 不代表默认；group_ids 只接受 null 或非空字符串组成的数组。错误类型和空 ID 必须报 IM_CONFIG_INVALID，不能因宽松空值定义放过错误配置。allowed_sender_ids 的 [] 仍拒绝所有发送者，null 非法；该字段是授权名单，不因群范围合同调整而放宽。

# 临时止损

需要先恢复指定群时，在原 Bot 完整配置中显式填写实际 group_ids，再按当前宿主的整个 Extra 重载流程应用。CLI extraset 会替换整份声明，必须保留其他 Bot、凭据、Context 和执行参数，不能只提交一个 group_ids 片段。CLI 的应用重启与 SDK 的 Extra 卸载重载按各自合同安排，避免打断在途任务。

此方法仅是待执行的止损建议，本轮未修改用户配置。不要放宽 allowed_sender_ids、删除真实 mention 门槛或重建 Home；不要用生产环境测试消息替代 im-test 验证。

# 发布与回退

代码修复前核对已运行任务和进程归属；构建/安装保留身份、Home、profile 和完整配置，不隐式安装 Provider。CLI 全局安装不会更新第三方 App 自带的 workspace/ASAR/SDK 副本，必须分别核对实际入口、运行构建号并重启受影响宿主，不能以“本机 CLI 已更新”宣称 SDK 产品已恢复。

如果修复后出现非预期准入，暂停升级，保留原字段配置及日志证据；必要时退回原发行物并保留显式 group_ids 止损。旧版本本身存在事故，直接回滚到 `6a4397d` 不能算恢复。回退不得改成允许所有发送者，也不删除会话、身份或用户数据。

历史被过滤消息不能通过重启恢复，需由用户明确重新发送；不得自动回扫群历史并执行旧请求，以免将普通交流或过期指令重新变成任务。

# 关闭条件

- 新合同回归及既有测试全部符合预期，必要构建、类型、lint、全量回归和发行包验收通过。
- im-test 的真实 payload 默认、null、空群范围路径通过；显式禁用/名单外/未授权/错 Space/无 @ 继续拒绝。
- CLI 与 SDK 各完成至少一次默认配置的实时 WS 接收、正常执行及原频道最终回复；话题回原话题，单消息不重复启动。
- 实际受影响宿主已加载修复版本；未升级的产品、未知首次发生时间和未统计影响范围如实保留，不假报全部恢复。
- 在事故记录中登记修复提交、验证环境/入口、恢复结果和未验项，更新当前合同；不改写此前交付记录的历史范围。
