# Runtime 日志按小时轮转与三小时保留

## 状态与已确认要求

状态：已实现，定向回归通过；真实进程及 im-test 验证以[交付记录](../../journal/shared/2026-10-16-hourly-log-delivery.md)为准。用户要求调试日志自动按 hour rotate，只保留最近 3 小时；随后明确每个文件最大 100 MiB。日志是短期排障材料，不建设持久归档、上传服务或复杂可配置保留系统。

审查发现 [host-log](../../../packages/octo-runtime-adapter-host/src/host-log.ts) 在 debug 开启后无限追加；[SDK supervisor](../../../packages/octo-runtime-daemon/src/runtime/supervisor.ts) 固定追加 embedded-runtime.log；[CLI service-control](../../../apps/cli/src/service-control.ts) 的固定输出文件也没有保留上限。只改 debug 文件仍不能关闭这次 review 的全部磁盘风险。

## 首版范围与保留口径

本计划建议将同一策略应用于 Runtime 自己创建的 Host debug、SDK 子进程输出和 CLI 托管服务输出。debug 默认仍关闭；普通诊断输出不会因此被强制开启为 debug。用户自行重定向终端输出、系统日志服务自己的保留以及 Provider 原生 session/数据库不由本任务删除或管理。

首版按“小时桶”落实最近 3 小时：保留当前小时和前两个小时，共最多 3 个文件/日志类别，实际覆盖最近 2 至 3 小时。这是简化实现的明确建议，不等同于逐条精确保留过去 180 分钟；若要求满 180 分钟需重新确定跨边界小时文件策略，不在实现时暗改为无限文件保留。

| 参数 | 首版合同 |
| --- | --- |
| 文件命名 | 日志类别 + UTC 小时标识，例如 adapter-host-20261016T07.log；文件内时间保留完整时间戳 |
| 保留 | 当前 UTC 小时及前两个小时；不因本机时区或夏令时重复命名 |
| 单文件 | 100 MiB = 104857600 字节，含换行；等于上限可写，大于时不写入该条 |
| 满额行为 | 本小时后续日志丢弃，不生成第二、第三个分片；下一小时恢复 |
| 磁盘界限 | 每个受管目录、每个日志类别最多 3 个文件，合计最多 300 MiB |
| 清理时机 | 启动、小时切换和至多每 60 秒检查一次；无新日志也会清理过期文件 |
| 写入失败 | 不影响 Agent 执行；只做有界脱敏诊断，不递归写自己的失败日志 |

此上限不是整个 Runtime Home 的 300 MiB 上限：不同日志类别分别受限，Provider 文件和用户文件也不计入。时钟倒退不允许制造第四个保留文件；按桶合法性与文件数量共同约束，不保留未来异常桶反复积累。删除/轮转失败必须保留受控诊断，不宣称磁盘上限已经生效。

## 实现方案

1. 用一个小型内部小时文件写入器统一日期、容量和清理规则，给各入口复用；不引入通用日志平台。每条写入前核对实际文件大小，重启后继承本小时已用容量，不能每次进程重启重新获得 100 MiB。
2. Host debug 使用同一写入器。关闭 debug 时不创建新的 debug 文件；已有新格式 debug 文件仍可由 Runtime 的受管日志清理路径处理。日志不新增图片 base64、凭据或 Context 归档，保持既有脱敏责任。
3. SDK supervisor 不再把子进程 stdout/stderr 永久绑定到 openSync(..., 'a') 的固定文件描述符。改为持续读取受管输出并交给小时写入器，退出时等待处理完成并释放监听和定时器。
4. CLI 托管服务由 launcher 承担受管输出写入，调整 service spec 的输出接线，避免 launchd/systemd 同时再向旧固定路径无限追加。前台 daemon run 继续保留终端输出和信号/退出码语义；不把前台体验改成只能去找日志。
5. 达到文件上限后继续排空子进程输出并丢弃，不能停止读取造成子进程阻塞，也不能把内容转存到无限内存队列。若采用异步写入，写队列须有明确小容量且满时丢日志；不得等待慢磁盘使 Agent 事件无限积压。
6. 扫描和删除只针对受管目录中本任务明确命名的普通日志文件，不跟随符号链接、不删其他文件。旧 adapter-host.log、embedded-runtime.log、service.out.log、service.err.log 停止获得新内容，但本次不自动删除既有文件或搬迁用户历史；保留剩余磁盘量与新增增长边界分别报告。

单小时满额无需复杂“丢弃记录账本”：最多保留一个内存标记/计数，下小时允许一条简短汇总。不得在已满文件外创建无限 overflow 日志。多个进程若可能写同一类别文件，M1 明确唯一写入归属或跨进程容量控制，不能各自按缓存大小超写。

实现使用同步小块追加，没有内存写队列；实际文件容量在非等待独占小时锁中核对，多个进程不能并发超写。锁竞争时丢弃该块；崩溃留下的小时锁保守停止该小时写入，下一小时恢复，过期锁随桶清理。写入/清理失败只报告一次短诊断；清理失败停止新增日志。日志目录及文件符号链接均拒绝，普通文件有多个硬链接时也不写。关闭后不再启动定时器，下次启动继续清理。

RPC trace 统一保留元数据，避免 canonical 图片/Context 因打开 debug 被归档。SDK 与 launcher 保持输出排空，等待 close；主进程已退出但后代仍持有输出管道时，最多排空 1 秒再关闭，防止旧监听和写入器悬挂。已有 CLI 原生服务需显式 daemon install 更新接线后重启，普通 start 不自动修复服务定义；本次不擅自改用户现有原生服务。

## 验收矩阵

| 场景 | 必须观察的结果 |
| --- | --- |
| debug 未开启、开启后输出 | 未开启不生成 debug 文件；开启按小时写入，无图片字节/凭据新增落盘 |
| 模拟连续运行 24 小时 | 每类别最多 3 个小时桶；清理不依赖恰好有新输出 |
| 100 MiB 前后、刚好等于上限 | 文件不超过 100 MiB；满后仍读取 stdout/stderr，下一小时恢复 |
| 同小时重启和多次重启 | 复用同桶和已用字节，不创建新分片绕过上限 |
| 时区变化、跨日、时钟前后跳 | 命名和清理确定；不积累无限文件 |
| 磁盘满、无权限、删除失败、符号链接 | 不递归报错、不删除越界文件；不假报轮转成功 |
| SDK/CLI 服务的真实子进程 | 新输出进入受管文件，旧固定路径不再增长；无输出管道阻塞 |
| 前台 daemon run、Ctrl+C、正常退出 | 终端行为、退出码和原有关闭语义保留；无残留 timer/监听 |

先以可控时钟和临时目录做测试，不真实等待 24 小时，也不操作用户现有 Home。使用专用测试 Home 和 im-test 做真实进程验收。macOS 的 launchd 实测不能冒充 Linux/Windows 已验收；对应服务生成测试必须更新，平台实测缺失在 journal 单列。

## 计划评分

95/100：周期、单文件 100 MiB、满额行为和自动清理已有可执行首版。剩余风险是小时桶与精确 180 分钟的产品口径、各进程输出接线及不同服务管理器的实机验证，不应只修一个 debug 文件就宣布风险全部关闭。
