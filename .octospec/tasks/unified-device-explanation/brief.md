# 目标与范围

用户需要直接讲清：之前是什么、目标是什么、设备能做什么，以及移动端 Buddy 确定性寻址和本地 IPC 为何需要统一设备。明确设备是机器上特定 Home 承载的执行实例；本地直接 IPC，其他设备经云端 WS/SSE 等通道接入。

开头按最新要求列出三个并列核心目标：本机应用通过本地 IPC 执行任务；IM Channel 接收 wukong-im Server 下发的消息并触发执行；可选注册设备为线上可用，让移动端 WorkBuddy 能指定设备对话。三个目标共用执行内核，线上登记不是本地调用或 IM 通道的前置条件。

移动端明确拆为 IM 对话和 conversation 跨端对话：前者经 wukong-im Server / IM Channel，后者像桌面本地对话一样通过 conversation 指定设备发起 AgentRun。业务价值表分别列出，图中拆分两个入口；旧架构中额外待建的移动端链路限定为 conversation 跨端对话，具体生产方案仍待确定。

用户补充旧 IM 基线：IM 走 OpenClaw 内置 Channel，没有统一设备概念。IM 本质触发 AgentRun，但执行位置隐含于 Bot / Channel；旧 Loop daemon 作为独立反例，不画成旧 IM 的执行链。

旧架构图按用户最新说明拆成三条实际链路：IM 内连 OpenClaw Channel；桌面 OctoBuddy 本地拉起 Codex App Server 并直接 IPC；Loop 使用独立、带 Loop 应用逻辑的 daemon 轮询执行。移动端尚未提供该能力，单独以虚线框及虚线节点标注达到 WorkBuddy 跨端效果需要额外实现一套远程接入、设备寻址与执行链路。Loop daemon 直接定义为 Loop 中专家执行业务任务的专用执行程序，正文不展开旧仓 checkout 或登记快照。

后续补充：核心目标之一是移动端发起远程 AgentRun，现有设备建模通过新增 Extra 支持。设备本地客观存在，云端登记只决定业务可见性及跨端寻址，注册失败不影响本地内核。所有流程图使用 TB，同类对象归入同一大框。

用户进一步强调：普适性是统一设备的关键标准。旧 Loop daemon 包含大量 Loop 应用业务逻辑，导致其他业务几乎无法直接统一使用；将其作为该服务不满足统一设备定义的首要原因，应用逻辑归 Extra / 业务服务。

具体反例是 Buddy / IM 复用旧 Loop daemon 时，调用必须转换为 Loop 调用模型，经云端服务，再由本机 daemon 轮询领取执行。同机调用仍绕云端，不满足核心目标 1 的本地直接 IPC。补充旧版每 Workspace 注册 Runtime 的历史问题，区分多个业务身份映射同一设备和一次请求重复执行；旧仓 TRD 已提出取消 Workspace 副本，不将历史模型描述为该仓当前合同。

按最新表达要求，讲解正文直接说明 Runtime 绑定 workspace_id、按 Workspace 登记副本造成设备身份与权限关系耦合，难以统一声明个人、组织或项目归属；移除该段的副本数量、执行次数及历史合同解释。TRD 作为来源链接保留，未核实加入 Workspace 后立即自动复制的具体触发机制，不作该断言。

设备登记与在线状态保持是当前可选接入模块的主要方向。按最新补充，考虑 Extra 层的独立模块与独立设备 Token；模块方案及 Token 合同待架构确认，不展开其他职责。远程服务经设备侧接入层再由本地调用内核，不直接连接 AdapterHost；本地 IPC 不以云端注册或设备 Token 为前置条件。

按最新要求删除讲解中 machineId / runtimeId 及其映射、归属、认证授权的整段说明。这些属于可选 Extra 的业务逻辑，非统一设备的必备模型；不因此修改现有代码、身份或配置。

本次只修改讲解入口及架构定义，不开发路由、发现或设备接入模块，不修改协议、身份与运行状态。

## 决定权与合同检查

- 需求来自业务选定执行位置及多个场景复用本地内核，属于设备定义与架构文档范围。
- 调用方及业务接入拥有目标选择、授权、云端路由与不可用时的处理策略；AdapterHost 拥有单次执行。
- 用户明确输入本地直连、异地云端转发及确定性寻址目标；不新增自动改投、自动等待或执行策略。
- 本次问题是文档将设备、物理机器和虚拟身份混用，在文档定义与示意图处纠正，不在代码下游增加兜底。
- 目标适用于多个业务场景，未改变现有 SDK、CLI 或 Extra 行为；没有新增默认、降级、重试或迁移动作。

## 验收

- `ARCHITECTURE.md` 包含旧 IM / 桌面 / Loop 三条独立执行链路、目标结构、寻址流程三图及业务价值表；移动端缺口单独用虚线标记。
- 旧架构主图只保留业务入口、执行实现两层大框，三对节点分别竖直连接；执行实现不再嵌套小框，避免自动布局将下层顺序反转造成交叉。
