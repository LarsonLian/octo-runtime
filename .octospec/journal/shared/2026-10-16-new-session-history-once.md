# IM 新会话历史一次补取决策

用户确认 IM reset 后仍补此前最近聊天，历史查询失败按空历史继续任务；历史作为辅助背景，不以效果不足阻断合法执行。正常续聊不重复自动拉取。最终补充要求为每个新 session 只自动尝试一次。

已更新[专项计划](../../tasks/channel-new-session-history/brief.md)与 context.yaml：最多 15 条纯文本，1500 字符包含标签/分隔符/截断标记，从最新向更早保留，边界消息可部分保留，最终按旧到新排列。首次资格由 Channel 在现有有界 session 状态中管理；请求前占用资格，成功、空结果及失败均消耗，并发与消息重投不重复请求。同一 Event 的重试复用冻结输入，不重新拉历史；Host 仍完整转发每次显式提交的 Context。

参考指定 openclaw-channel-octo 的 inbound.ts：已核对 API 补取失败后继续处理；该插件的逐轮历史、reset watermark 过滤与本次决策不同，不移植。本次 1500 字符裁剪是用户明确的新约束，不描述为旧插件现有能力。

同步目录、会话规则、固定目录决策及 mention 指引，移除 reset 历史过滤待决表述。本次未修改业务实现、发送消息或执行线上调试；实现与真实分页语义仍待在 im-test 验收。

用户进一步澄清本项目全新且无人使用，撤回助手添加的旧 history_limit 兼容与迁移要求。历史专项直接替换旧逐轮策略，同步配置定义、样例和测试，不保留兼容模式；该事项不再计为计划缺口。本次仅修正文档，不据此删除运行数据或修改其他功能的发布约束。
